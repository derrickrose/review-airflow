# assets scheduling

## what is ?

- cron expressions (at which specific time like everyday at midnight)
- Timedelta object (each 3 days at 12:00)
- Timetables (advanced scheduling) (schedule exactly as you want but very complex)
- what if you want to schedule your DAGs based on data updates ?
    - receive a file and you want to trigger a DAG based on it
    - there comes the asset
- Dags that access the same data can have explicit and visible relationships and can be scheduled based on these assets
- this feature makes airflow asset-aware and expands airflow scheduling capabilities beyond time-based methods.

## asset

- 2 data pipelines
- pipeline 1 is scheduled daily and generates a file
- pipeline 2 is triggered by a file generated by pipeline 1
- so here the asset is the file generated by pipeline 1 (modification too is an asset) then will trigger pipeline 2
- basically you can create dependencies between multiple dags based assets event, assets update
- this is very useful if you rely on ExternalTaskSensor or TriggerDagRunOperator

## why ?

- assets allow you to define explicit dependencies between dags and updates to your data
- this helps to
    - standardize communication between teams (can function like a contract or API to communicate between teams)
    - reduce amount of code to implement cross-dag dependencies
    - get better visibility into how your dags are connected and how they depend on data
- reduce costs, because assets dont use resources (worker slot) in contrast to sensors
- create cross-deployment dependencies using the airflow REST API (can trigger a dag in a different airflow deployment)
- create complex event-driven scheduling

## how to ?

- an asset is an objet that is defined by a unique name.
- optionally an URI can be attached to it when it represents a concrete data entity (file, table in db, etc.)

```python
from airflow.sdk import asset 

asset = Asset(name="my_asset", uri="file://path/my_file.csv", group="my_group")

# The asset must define either `name` or `uri`; at least one of them is required.
# The `group` field is optional and can be used to logically organize assets.
# The `uri` represents a unique resource identifier—for example, a local file path, a database object, or any other uniquely addressable resource.
# As a best practice, when an asset corresponds to an actual system entity, you should set `uri` to establish a direct link to the entity in the underlying system.
```

```python
from airflow.sdk import asset

@asset(@schedule=@daily, uri="file://path/my_file.csv", group="my_group")
def my_asset():
    return "my_asset"

# when using the @asset decorator, Airflow creates a DAG with a single task corresponding to the Asset
# that's why you must define a schedule parameter, it determines the frequency at which the asset should be materialized 
# for example if the asset downloads data from an API and stores it in a file, materializing means trigger the dag with the task to download the data to the file

```

## materializing an asset

- triggering the task that do the logic task assigned to the asset (example here running the dag which create the file)
- this materialization will create an Asset Event
- an event is attached to an asset and created whenever a task updates that particular asset
- an asset event is defined by being attached to a specific asset plus the timestamp of when a task updated the asset
- example we have a dag with a task, that task updates an asset, and that triggers a downstream dag with another tasks
- the code bellow is a sample to read the asset event that was received from upstream dag

```python
#(not used by mark by might be necessary  for data lineage)
from datetime import datetime, timedelta

from airflow import Asset
from airflow.sdk import task, dag

@dag(
    dag_id="my_downstream_dag",
    start_date=datetime(2024, 1, 1),
    catchup=False,
    dagrun_timeout=timedelta(minutes=60),
    schedule=[Asset("my_first_asset", uri="file:///opt/airflow/data/a.txt")], # note dhe schedule is the asset
)
def my_downstream_dag():

    # intlets for consumer
    @task(inlets=[Asset("my_first_asset", uri="file:///opt/airflow/data/a.txt")])
    def get_extra_inlet(inlet_events):
        for asset, asset_list in inlet_events.items():
            if asset_list[-1].timestamp > asset_list[0].timestamp:
                    print(f"Asset {asset} was updated at {asset_list[-1].timestamp}")
                    print(asset, asset_list)
                    print(asset, asset_list[-1].extra)
                    print(asset, asset_list[-1].timestamp)
                    print(asset, asset_list[0].source_run_id)
    get_extra_inlet()
my_downstream_dag()

```

- this code bellow is a code to update an asset through a dag, using asset outlets
- note that extra information can be sent with the asset event , Metadata can be added to the asset event with yield

```python
from datetime import datetime, timedelta

from airflow.sdk import dag, Asset, task

@dag(
    dag_id="asset_update",
    start_date=datetime(2024, 1, 1),
    catchup=False,
    dagrun_timeout=timedelta(minutes=60),
)
def asset_update():

    @task(outlets=[Asset("my_first_asset", uri="file:///opt/airflow/data/a.txt")])
    def update_asset():
        print("Hello world")

        with open("/opt/airflow/data/a.txt", "w") as f:
            f.write(f"Hello world {datetime.now()} \n")
        print("file updated")

    update_asset()
asset_update()
```
